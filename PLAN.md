## 0. Роль и цель (вставить агенту первым сообщением)

Ты — senior full-stack TypeScript разработчик. Построй **UzMonopoly** — браузерную мультиплеерную настольную игру в стиле Монополии с узбекской тематикой.

Ключевые требования:

- Комнаты (лобби): создать комнату, зайти по коду или ссылке, **от 2 до 6 игроков** в одной игре.
- Игра в реальном времени (WebSocket), пошаговая.
- **Вся игровая логика только на сервере** (server-authoritative). Клиент лишь отправляет намерения и рисует состояние.
- Минимальные расходы на хостинг: целевой бюджет **$0–6 в месяц**.
- Интерфейс на трёх языках: **узбекский (латиница), русский, английский**.
- Работает на телефоне и на компьютере.

Работай по фазам из раздела 7. Не переходи к следующей фазе, пока тесты текущей не зелёные.

## 2. Важные решения по доске

В списке **14 групп по 3 компании = 42 владения**. В классической Монополии их 28 на 40 клеток, поэтому **доска увеличивается до 52 клеток** (по 12 клеток на сторону + 4 угла):

- 4 угла
- 42 компании (14 групп по 3)
- 2 клетки «Imkon» (Шанс)
- 2 клетки «Xazina» (Общественная казна)
- 2 клетки налога

Железных дорог и коммунальных служб в классическом виде нет: все 42 владения работают как обычные улицы (строительство, цветовые группы). Группа из 3 компаний даёт «монополию» (удвоенная аренда без построек и право строить), если все 3 принадлежат одному игроку.

> Все названия, цены и тексты лежат в `packages/engine/src/data/board.ts` и `cards.ts` как данные, а не в коде. Это нужно, чтобы названия можно было менять без правки логики (см. раздел 9 про бренды).

## 4. Правила игры (что должен реализовать движок)

1. **Порядок хода**: бросок двух кубиков, перемещение, действие клетки, затем необязательные действия (строить, залог, обмен), затем «закончить ход».
2. **Дубли**: бросок дубля даёт ещё один ход. Три дубля подряд отправляют в тюрьму.
3. **Покупка**: игрок встал на свободную компанию и может купить по цене. Если отказался, **начинается аукцион** среди всех игроков (шаг ставки, таймер 20 секунд, можно пасовать).
4. **Аренда**: платится владельцу, если компания не в залоге и владелец не в тюрьме по правилу «в тюрьме аренду собирают» (включить, это стандартное правило).
5. **Тюрьма**: выйти можно заплатив 100, бросив дубль (до 3 попыток) или карточкой «Освобождение». После 3-й неудачной попытки обязан заплатить 100.
6. **Imkon и Xazina**: колода из 16 карточек, тасуется при старте. Карточка «Освобождение из тюрьмы» удерживается игроком.
7. **Налоги**: платятся в банк.
8. **Обмен (trade)**: между двумя игроками: деньги + компании + карточки «Освобождение». Принимает или отклоняет второй игрок. Компании с постройками в обмен не идут, пока постройки не проданы.
9. **Залог и банкротство**: при долге игрок обязан продать постройки / заложить компании. Если не хватает, он **банкрот**: всё имущество переходит кредитору (или банку, у которого оно выставляется на аукцион).
10. **Победа**: остался один игрок. Дополнительно: режим «короткая игра» по таймеру (например, 45 минут) с победой по общей стоимости активов.
11. **Таймер хода**: 60–90 секунд (настройка комнаты). По истечении автоматически выполняется безопасное действие (бросок, отказ от покупки, закончить ход).
12. **Отключение**: игрок отключился, держим место 60 секунд для возврата. Потом бот доигрывает простыми правилами (покупает, если денег хватает с запасом, не строит рискованно).

## 5. Сетевой протокол и лобби

### Лобби

- Главный экран: «Создать комнату», «Войти по коду», список публичных комнат.
- Создание комнаты: ник, максимум игроков (2–6), приватная/публичная, длина таймера хода, режим (полная / короткая).
- Код комнаты: 5 символов (A–Z, 2–9, без похожих O/0, I/1). Ссылка вида `/room/ABCDE`.
- Внутри лобби: список игроков, выбор фишки и цвета, кнопка «Готов», хост может выгнать игрока и нажать «Начать» (минимум 2 готовых).
- Фишки (6): do'ppi (тюбетейка), choynak (чайник), qozon (казан), tarvuz (арбуз), Damas (машина), Tulpar (крылатый конь).
- Гостевой вход: ник + случайный токен в localStorage для переподключения. Аккаунты не нужны.

### Протокол (Colyseus messages, все проверять через zod)

Клиент → сервер (намерения):
`ready`, `setToken`, `startGame`, `rollDice`, `buy`, `declineBuy`, `bid {amount}`, `passAuction`, `build {tileId}`, `sellBuilding {tileId}`, `mortgage {tileId}`, `unmortgage {tileId}`, `proposeTrade {...}`, `answerTrade {id, accept}`, `payJailFine`, `useJailCard`, `endTurn`, `chat {text}`.

Сервер → клиент:

- `state` — полный снимок состояния игры с номером `seq` (он небольшой, <20 КБ, поэтому патчи не нужны в MVP).
- `event` — журнал событий для анимаций и лога («Игрок X бросил 3+4», «заплатил аренду 26»).
- `error {code}` — отказ действия с причиной.

Правила сервера:

- Каждое сообщение проверяется: чей сейчас ход, допустимо ли действие в текущей фазе, хватает ли денег.
- Кубики бросаются на сервере (`crypto.randomInt`), клиент ничего не решает.
- Ограничение частоты сообщений (rate limit) на игрока.
- Скрывать нечего (в Монополии нет скрытой информации), поэтому всем рассылается один и тот же снимок.

## 6. Модель игры в движке (`packages/engine`)

Движок = **чистая функция**: `applyAction(state, playerId, action, rng) -> { state, events } | { error }`. Никаких таймеров, сети, `Date.now()` внутри (время и случайность передаются снаружи, чтобы тесты были детерминированными).

Основные типы:

```ts
type Phase =
  | 'LOBBY'
  | 'ROLL'
  | 'MOVING'
  | 'BUY_DECISION'
  | 'AUCTION'
  | 'POST_ROLL'
  | 'JAIL'
  | 'DEBT'
  | 'GAME_OVER';

interface Player {
  id: string;
  name: string;
  token: TokenId;
  color: string;
  cash: number;
  position: number;
  inJail: boolean;
  jailTurns: number;
  jailCards: number;
  bankrupt: boolean;
  connected: boolean;
}

interface TileState {
  ownerId?: string;
  houses: number;
  mortgaged: boolean;
} // houses 5 = отель

interface GameState {
  seq: number;
  phase: Phase;
  players: Player[];
  turnIndex: number;
  doublesCount: number;
  tiles: Record<number, TileState>;
  auction?: {
    tileId: number;
    highBid: number;
    highBidder?: string;
    active: string[];
    endsAt: number;
  };
  pendingTrade?: TradeOffer;
  pendingDebt?: { debtor: string; creditor?: string; amount: number };
  decks: { imkon: number[]; xazina: number[] };
  log: GameEvent[];
  settings: RoomSettings;
}
```

Требования к тестам движка (обязательно, это самая рискованная часть):

- Проход через «Boshlash», три дубля, выход из тюрьмы всеми способами.
- Аренда с монополией, с домами, с отелем, залог.
- Равномерная застройка и продажа.
- Аукцион (несколько игроков, ничья ставок, все пасуют).
- Обмен с проверками.
- Банкротство перед игроком и перед банком, цепочка банкротств, определение победителя.
- Property-based тест (fast-check): сумма денег + стоимость купленного не создаётся из воздуха, нет отрицательных денег у не-банкротов, дома не превышают лимит банка.
- Прогон 1000 партий из ботов с фиксированными seed без падений и зависаний (проверка, что игра заканчивается).

## 7. Фазы работы (по одной за раз)

### Фаза 1. Каркас и данные

- Создать монорепо, настроить TypeScript strict, ESLint, Prettier, Vitest, CI.
- В `engine/data` описать доску (раздел 3), карточки (раздел 4), конфиг.
- Тест: все 52 клетки заполнены, у каждой группы ровно 3 компании, цены неубывающие по кругу.
- **Результат**: зелёный CI, отчёт-артефакт со схемой доски.

### Фаза 2. Игровой движок

- Реализовать `applyAction` для всех действий (раздел 4), покрыть тестами (раздел 6).
- Реализовать простого бота (`engine/bot.ts`) и симулятор партий.
- **Результат**: 1000 симулированных партий без ошибок, отчёт по среднему количеству ходов и распределению побед (для балансировки).

### Фаза 3. Сервер и лобби

- Colyseus `LobbyRoom` + `GameRoom`: создание, код, вход, выбор фишки, готовность, старт, выгнать.
- Подключение движка, таймеры хода и аукциона, переподключение (60 с), замена отключившегося ботом.
- Тесты сервера: 6 клиентов в одной комнате проходят партию, переподключение в середине хода.
- **Результат**: запись консольного прогона 6 тестовых клиентов.

### Фаза 4. Клиент: лобби и поле

- Экраны: главная, создание/вход, лобби комнаты.
- Поле 52 клетки на SVG/CSS (адаптивно, на телефоне поле масштабируется, действия внизу), фишки, кубики с анимацией, панели игроков, лог событий, чат.
- **Результат**: скриншоты на ширине 390 px и 1440 px.

### Фаза 5. Клиент: игровые действия

- Окна покупки, аукциона, обмена, карточки Imkon/Xazina, управление зданиями и залогом, окно долга, экран победы.
- Подсказки «почему нельзя» (серые кнопки с причиной).
- **Результат**: Playwright e2e: 3 вкладки проходят партию до победителя.

### Фаза 6. Полировка и i18n

- Переводы uz / ru / en для всех текстов, звуки (выключаемые), тёмная тема, доступность (контраст, клавиатура).
- Узбекский орнамент (сюзани, ikat) как фон и рамки поля, без копирования дизайна Hasbro.
- **Результат**: переключение языка в лобби и в игре.

### Фаза 7. Деплой

- Dockerfile сервера, Caddy с авто-HTTPS, `docker compose up -d`.
- Клиент на Cloudflare Pages, переменная `VITE_SERVER_URL`.

## 8. Что можно сделать, чтобы расходы были минимальными

- Один маленький VPS (1–2 vCPU, 1–2 ГБ RAM) выдерживает сотни одновременных комнат: сообщения короткие, игра пошаговая.
- Всё состояние в памяти, без базы данных в MVP.
- Статика клиента на Cloudflare Pages (бесплатно). Домен ~$10–15 в год.
- Без видео/голоса и без тяжёлых ассетов. Графика: SVG и CSS.
- Бесплатные тарифы с засыпанием сервера неудобны для WebSocket, поэтому лучше платный VPS за $4–6.

## 9. Риски и юридические моменты (учесть сразу)

1. **Названия реальных компаний и торговые марки.** Uzum, Yandex, Visa, Uzcard, Humo, Payme, Click, KIA, BYD, Beeline и другие — зарегистрированные бренды. Для личного проекта и закрытого тестирования это обычно не проблема, но при публичном запуске / монетизации возможны претензии. Рекомендации: использовать только текстовые названия **без логотипов и фирменных цветов**, добавить в футер дисклеймер («Проект не связан с упомянутыми компаниями, названия используются в игровых целях»), а в коде держать названия в одном файле данных, чтобы при необходимости быстро заменить их на вымышленные.
2. **Название и дизайн Monopoly** принадлежат Hasbro. «UzMonopoly» содержит слово Monopoly, поэтому при публичном запуске есть риск. Подготовьте запасное название (например, «UzBiznes» или «Biznes Shahar») и вынесите его в конфиг.
3. **Рассинхронизация и переподключение.** Самая частая проблема в онлайн-играх: тестировать с отключением сети.
4. **Аукционы и обмены.** Самые сложные части: в MVP можно временно упростить, но не пропускать.
5. **Защита**: серверная валидация, rate limit, ограничение длины ника и чата, фильтр оскорблений.
